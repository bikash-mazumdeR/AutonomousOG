# SKILL: Playwright UI Automation Script Generator
## Agent ID: 05-playwright-script-generator-ui
## Version: 3.0.0
## Classification: Core — UI Test Generation (TypeScript)

---

## 🎯 SKILL PURPOSE

Transform enriched UI test cases (Positive, Negative, Edge, Functional, Security, Accessibility) into **production-grade Playwright TypeScript specs (`.spec.ts`)** paired with strongly-typed **Page Object Model (POM) classes (`Page.ts`)**.

Every generated UI script must be:
- Executable via `npx playwright test` with zero manual modification
- Strictly separated into Spec (assertions & orchestration) and POM (selectors & action primitives)
- Compliant with Playwright strict mode (1:1 element resolution) and web-first assertions
- Thread-safe for parallel execution across isolated browser contexts
- Written in clean, idiomatic TypeScript with proper typing (`Page`, `Locator`)

---

## 📦 BATCH GENERATION WORKFLOW

When test cases exceed `FRAMEWORK_CONFIG.specBatchSize` (default: 10), generation occurs across consecutive batches to prevent LLM token truncation.

```
Total TCs: N  |  Batch Size: 10  →  Batches: 1..M
- Batch 1     → FULL_FILE mode: Complete spec wrapper (imports, fixtures, describe, hooks, batch 1 tests, closing });)
- Batch 2..M  → TEST_BLOCKS_ONLY mode: Raw test() blocks ONLY — appended before final }); of Batch 1
```

### Batch Mode Rules

| Mode | Allowed Content | Strictly Prohibited Content |
|---|---|---|
| `FULL_FILE` | `'use strict'`, imports, `test.extend`, `test.use`, `describe`, hooks, `test()` blocks | Conversational preambles, inline POM classes |
| `TEST_BLOCKS_ONLY` | Raw `test('{tcName}', { ... }, async ({ featurePage }) => { ... });` | Conversational text, require/imports, `test.describe()`, `test.use()`, closing `});` |

> **Enforcement:** Each batch is validated by AST rule `COMPLETENESS-001` against `context.batchTCKeys`. Omission of any TC key triggers an immediate retry.

## 📐 PLAYWRIGHT UI SPEC TEMPLATE (TypeScript)

```typescript
'use strict';

/**
 * @fileoverview {FeatureName} — Playwright UI Automation Spec
 * Generated by ARIA Agent 05 | TC Keys: {tcKeys}
 * Feature: {featureId} | Risk: {riskLevel}
 * @module {FeatureName}Spec
 */

import { test as base, expect } from '@playwright/test';
import { {FeatureName}Page } from '../pages/{FeatureName}Page';
import testData from '../fixtures/test-data.json';

// Reusable fixture injection with TypeScript types
const test = base.extend<{ featurePage: {FeatureName}Page }>({
  featurePage: async ({ page }, use) => {
    await use(new {FeatureName}Page(page));
  },
});

test.describe('{FeatureName}', () => {
  test.beforeEach(async ({ featurePage }) => {
    await featurePage.navigate(testData.baseURL);
  });

  test.afterEach(async ({ page }, testInfo) => {
    if (testInfo.status !== testInfo.expectedStatus) {
      const sanitizedTitle = testInfo.title.replace(/[^a-zA-Z0-9_-]/g, '_');
      await page.screenshot({
        path: `reports/attachments/screenshots/${sanitizedTitle}-${Date.now()}.png`,
        fullPage: false,
      });
    }
  });

  // ── TC-001: [Type] Test Case Name ────────────────────────────────────
  test('{tcName}', {
    tag: ['@{label1}', '@{label2}'],
    annotation: [
      { type: 'TC Key',   description: '{tcKey}' },
      { type: 'Feature',  description: '{featureId}' },
      { type: 'Story',    description: '{storyId}' },
      { type: 'Priority', description: '{priority}' },
    ],
  }, async ({ featurePage }) => {
    await expect(featurePage.submitButton).toBeEnabled();
    await featurePage.fillForm(testData.standardUsername, testData.password);
    await expect(featurePage.successBanner).toBeVisible();
    await expect(featurePage.successBanner).toContainText('Success');
  });
});
```

## 📐 PAGE OBJECT MODEL (POM) TEMPLATE (TypeScript)

```typescript
'use strict';

/**
 * @fileoverview {PageName} Page Object Model
 * @module {PageName}Page
 */

import { Page, Locator } from '@playwright/test';
import { BasePage } from './BasePage';

export class {PageName}Page extends BasePage {
  constructor(page: Page) {
    super(page);
  }

  // Locators — defined exclusively as getters with Locator return type
  get usernameInput(): Locator  { return this.page.locator('[data-test="username"], [data-testid="username"], #user-name'); }
  get passwordInput(): Locator  { return this.page.locator('[data-test="password"], [data-testid="password"], #password'); }
  get submitButton(): Locator   { return this.page.locator('[data-test="login-button"], #login-button'); }
  get successBanner(): Locator  { return this.page.locator('[data-test="inventory-container"]').first(); }
  get errorMessage(): Locator   { return this.page.locator('[data-test="error"]'); }

  // Action Methods (STRICTLY NO ASSERTIONS IN POM)
  async navigate(url: string): Promise<void> {
    await this.page.goto(url);
  }

  async fillForm(username: string, password: string): Promise<void> {
    await this.usernameInput.fill(username);
    await this.passwordInput.fill(password);
    await this.submitButton.click();
  }
}
```

## 🎯 LOCATOR STRATEGY HIERARCHY

Select locators using this priority order (1 = highest, 8 = lowest):

```
1. page.getByTestId('data-testid')              ← Resilient to UI/copy refactors
2. page.getByRole('button', { name: 'Submit' })   ← Semantic accessibility role + name
3. page.getByLabel('Username')                  ← Associated form label
4. page.getByPlaceholder('Enter username')      ← Input placeholder text
5. page.getByText('Welcome back')               ← Distinct visible text
6. page.locator('[aria-label="Close dialog"]')  ← ARIA accessibility attributes
7. page.locator('.btn-primary')                 ← Scoped CSS class (stable classes only)
8. page.locator('#unique-id')                   ← Stable unique element ID

STRICTLY FORBIDDEN:
× Positional or indexed XPath: //div[3]/span[2]
× Absolute CSS selector paths: div > div > form > button
× Comma-separated multi-selectors that collide and violate Playwright strict mode
```

## 📏 UI CODE QUALITY & DESIGN RULES

1. **Reusable Fixtures Only:** Inject POM instances via `base.extend<{ featurePage: FeaturePage }>({ featurePage })`. Never instantiate POM with `new Page(page)` inside individual tests.
2. **TypeScript Native:** Write clean, typed TypeScript without conversational preambles.
3. **Fixtures Only Test Data:** Always import test data via \`import testData from '../fixtures/test-data.json';\`. STRICTLY PROHIBIT declaring or inlining \`const testData = { ... }\` in the spec file. Reference flat keys directly (e.g. \`testData.baseURL\`, \`testData.standardUsername\`). Never nest under \`testData.global\` or \`testData.perTC\` and never hardcode URLs.
4. **Strict POM Method Compliance:** Specs may only invoke methods and getters explicitly defined on the Page Object.
5. **Mandatory Web-First Assertions:**
   - Always assert locators: `await expect(locator).toBeVisible()`, `await expect(locator).toBeEnabled()`.
   - NEVER query boolean states (`const v = await isVisible(); expect(v).toBe(true)`).
   - NEVER call `.toContain(true)` or `.toContain(false)` (throws uniterable `TypeError`).
6. **Requirement-Driven Step Ordering:** When testing component states (enabled, disabled, masked), assert initial state on page load before triggering inputs or submissions.
7. **True Concurrency Testing:** Request `{ browser }` fixture, create distinct contexts via `await browser.newContext()`, and run actions concurrently via `Promise.all([ ... ])`.
8. **Negative Form Testing:** Populate all non-targeted required fields with valid values so validation failure isolates the intended field.
9. **Specialized Criteria Enforcement:** Never fallback to boilerplate login for accessibility (WCAG), security (HTTPS/cookies), or responsive viewport tests:
   - For TLS 1.2+ tests: Verify the negotiated TLS protocol via `await response.securityDetails().catch(() => null)`. When present, assert `expect(['TLS 1.2', 'TLS 1.3'].some(p => security.protocol.includes(p))).toBeTruthy()`; when omitted by headless/CI runners, fall back to `expect(new URL(page.url()).protocol).toBe('https:')`.
   - For input field acceptance tests: Directly assert field value via `await expect(locator).toHaveValue(expectedValue)` rather than executing a full login flow.
   - For WCAG 2.1 Level AA accessibility tests: Perform automated accessibility tree scanning via `await page.accessibility.snapshot()` and assert accessible roles (`textbox`, `button`) and keyboard focus navigation (`Tab` sequence) using Playwright's native APIs.
10. **Unauthorized Redirection:** When verifying direct access to protected routes or expired sessions, verify redirection to the login URL (`await expect(page).toHaveURL(testData.baseURL)`) and confirm login form elements (`usernameInput.toBeVisible()`, `loginButton.toBeVisible()`). Do not rely solely on error banner messages.
11. **Page Reload Stabilization:** Always follow `await page.reload()` with `await page.waitForLoadState('domcontentloaded')` before interacting with or asserting on DOM elements.
12. **Resilient Color Assertion:** When asserting computed styles (e.g. background-color), normalize RGB/RGBA to Hex or accept multiple format representations.
