# SKILL: Playwright API Test Script Generator
## Agent ID: 05-playwright-script-generator-api
## Version: 3.0.0
## Classification: Core — API & Integration Test Generation (TypeScript)

---

## 🎯 SKILL PURPOSE

Generate standalone, high-performance **Playwright API test specs (`*-api.spec.ts`)** for test cases of type `API`, `Integration`, and `Contract`.

Playwright API tests execute HTTP requests directly via Playwright's built-in `request` fixture, bypassing browser orchestration entirely for sub-second execution speeds.

---

## 🚫 STRICT ARCHITECTURAL CONSTRAINTS

| Rule | Requirement |
|---|---|
| **NO Page Object Model** | API tests must NEVER import or instantiate POM classes (`*Page.ts`). |
| **NO `page` Fixture** | Do not request `{ page }` or `{ browser }`. Only request `{ request }`. |
| **TypeScript Native** | Output clean TypeScript (`.ts`) syntax with ES imports. |
| **Concrete Endpoints** | Only generate specs when concrete endpoints (e.g. `/api/v1/orders`) are confirmed. Never hallucinate fake paths. |
| **Flat `testData` Keys** | Access `testData.baseURL`, `testData.apiHeaders`, `testData.authPayload` directly. |

## 📐 PLAYWRIGHT API SPEC TEMPLATE (TypeScript)

```typescript
'use strict';

/**
 * @fileoverview {FeatureName} — Playwright API Automation Spec
 * Generated by ARIA Agent 05 | TC Keys: {tcKeys}
 * Feature: {featureId} | Type: API / Contract
 * @module {FeatureName}ApiSpec
 */

import { test, expect, APIResponse } from '@playwright/test';
import testData from '../fixtures/test-data.json';

test.describe('{FeatureName} — API', () => {
  // ── TC-001: [API] Test Case Name ────────────────────────────────────
  test('{tcName}', {
    tag: ['@{label1}', '@{label2}'],
    annotation: [
      { type: 'TC Key',   description: '{tcKey}' },
      { type: 'Feature',  description: '{featureId}' },
      { type: 'Story',    description: '{storyId}' },
      { type: 'Priority', description: '{priority}' },
    ],
  }, async ({ request }) => {
    const startTime = Date.now();

    // 1. Execute HTTP request via Playwright request fixture
    const response = await request.post(`${testData.baseURL}/api/{endpoint}`, {
      data: {
        username: testData.standardUsername,
        password: testData.password,
      },
      headers: {
        'Content-Type': 'application/json',
        Accept: 'application/json',
      },
    });

    const durationMs = Date.now() - startTime;

    // 2. Status code assertion
    expect(response.status()).toBe(200);

    // 3. Response time SLA assertion
    expect(durationMs).toBeLessThan(1000);

    // 4. Response body parsing & JSON schema / field assertions
    const body = await response.json();
    expect(body).toBeDefined();
    expect(body).toHaveProperty('token');
    expect(typeof body.token).toBe('string');
    expect(body.token.length).toBeGreaterThan(0);
  });
});
```

## 📏 API QUALITY & ASSERTION RULES

1. **Direct Status Code Checks:** Assert `expect(response.status()).toBe(expectedStatus)` or `expect(response.ok()).toBeTruthy()`.
2. **Schema & Property Verification:** Validate top-level keys, nested objects, and array lengths using `toHaveProperty`, `toBeInstanceOf(Array)`, or `toMatchObject`.
3. **Response Time SLA Verification:** Track request duration (`Date.now() - startTime`) and assert against quantitative criteria (`expect(durationMs).toBeLessThan(...)`).
4. **Header & Content-Type Checks:** Verify `response.headers()['content-type']` matches expected MIME types (e.g. `application/json; charset=utf-8`).
5. **Negative Status Handling:** For negative tests (e.g. 400 Bad Request, 401 Unauthorized, 404 Not Found), assert status code and error message structure:
   ```javascript
   expect(response.status()).toBe(400);
   const errBody = await response.json();
   expect(errBody.error).toMatch(/invalid credentials/i);
   ```
