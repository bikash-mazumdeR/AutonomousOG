## 🎯 SKILL PURPOSE

Perform a comprehensive static code review of all Playwright spec files,
Page Object Model classes, and K6 scripts generated by Agent 05 — acting

## 🧠 REVIEW DIMENSIONS (9 Total)

### Dimension 1: Locator Quality
```
PASS criteria:
□ No XPath with positional index (/div[3]/span[2])
□ No absolute CSS chains (div > div > div > button)
□ No nth-child positional selectors beyond index 2
□ Preferred order respected: testid > role > label > placeholder > text > css
□ All locators defined in POM getters — none inline in spec files
□ No hardcoded URLs inside locators

FLAG (MAJOR):
□ CSS class-only selector (.btn-primary) without a stable attribute
□ Text locator for a button (use role instead)

BLOCK (BLOCKER):
□ XPath used anywhere
□ Positional index locator (nth-child > 3)
□ Locator inside test body — not in POM
```

### Dimension 2: Wait Strategy
```
PASS:
□ page.waitForSelector / waitForResponse / waitForURL used
□ waitForLoadState used after navigation
□ No arbitrary page.waitForTimeout() > 500ms

FLAG (MAJOR):
□ page.waitForTimeout(x) where x > 500ms — replace with proper wait

BLOCK (BLOCKER):
□ page.waitForTimeout(x) where x > 5000ms (hard sleep)
□ No wait after navigation or async action
```

### Dimension 3: Assertion Quality
```
PASS:
□ All assertions use expect() from @playwright/test
□ Assertions are specific (toHaveText vs toBeVisible for text)
□ Every test has at least 1 assertion
□ Negative TCs assert the error state, not the success state

FLAG (MAJOR):
□ Only asserting page URL when test should assert UI state
□ Missing assertion on a test step with "verify" in its description

BLOCK (BLOCKER):
□ console.assert() used instead of expect()
□ Test has zero assertions
□ Positive TC uses same assertion as Negative TC
```

### Dimension 4: POM Compliance
```
PASS:
□ All POM classes extend BasePage
□ All locators are getter properties
□ No direct page.locator() in spec file body
□ Action methods exist for all interactions
□ Constructor calls super(page, 'ClassName')

FLAG (MAJOR):
□ POM method > 30 lines — split required
□ Locator defined inside an action method (not as getter)

BLOCK (BLOCKER):
□ POM class does not extend BasePage
□ Locator defined inline in test() block
```

### Dimension 5: Data Usage
```
PASS:
□ All test data sourced from flat testData (e.g. testData.baseURL, testData.standardUsername, testData.password)
□ No hardcoded PII (real emails, real passwords)
□ No hardcoded environment URLs (use testData.baseURL)
□ Runtime secrets referenced via process.env.* — not hardcoded

FLAG (MAJOR):
□ Hardcoded string that looks like a URL
□ Test data value > 50 chars inline (should be in fixture)

BLOCK (BLOCKER):
□ Hardcoded password or token string
□ Real email address in test file
```

### Dimension 6: Error Handling & Resilience
```
PASS:
□ try/catch on API request assertions
□ afterEach takes screenshot, network log, console log on failure
□ test.retry configured via playwright.config.js (not inline)
□ Network capture attached (BasePage._attachCaptures() called)

FLAG (MAJOR):
□ Missing afterEach screenshot on failure
□ No console log capture

BLOCK (BLOCKER):
□ Empty catch block that swallows errors
□ No afterEach cleanup/capture block in spec
```

### Dimension 7: Parallel Safety
```
PASS:
□ No shared mutable state between test blocks
□ Each test creates its own POM instance in beforeEach
□ No global variables mutated across tests
□ Fixture data is read-only (no writes in test body)
□ test.describe.serial() only used when documented with reason

FLAG (MAJOR):
□ let variable declared outside test block and mutated inside

BLOCK (BLOCKER):
□ Shared object mutated across parallel tests
□ Static class variable written during test execution
```

### Dimension 8: K6 Script Quality
```
PASS:
□ All thresholds use __ENV.* (not hardcoded numbers)
□ vus and duration use __ENV.K6_VUS / K6_DURATION
□ check() used for all assertions
□ sleep(1) present to avoid hammering server
□ handleSummary() implemented for JSON output
□ No import from local files (K6 uses ES modules, no CommonJS)

FLAG (MAJOR):
□ No sleep() between iterations
□ Missing check() for response status

BLOCK (BLOCKER):
□ Hardcoded threshold numbers (not from __ENV)
□ require() used instead of import in K6 script
□ Missing handleSummary() function
```

### Dimension 9: Code Style & JSDoc
```
PASS:
□ 'use strict' present in all .js files
□ JSDoc on all exported classes and public methods
□ No console.log in spec files (use testInfo.attach for debug)
□ Max file length: 400 lines per spec, 200 lines per POM
□ Max method length: 30 lines
□ Consistent single-quote strings
□ No unused variables (no-unused-vars)
□ Async/await throughout — no callbacks or .then()

FLAG (MINOR):
□ Missing JSDoc on a public method
□ console.log present in spec file

BLOCK (MAJOR):
□ .then() callback used instead of await
□ File > 400 lines (spec) or > 200 lines (POM) without justification
```

## 🔧 AUTO-PATCH CAPABILITIES

This agent can automatically fix certain categories of issues:

| Issue | Auto-Fix |
|---|---|
| `page.waitForTimeout(x)` where x < 2000 | Replace with `waitForLoadState('networkidle')` |
| Missing `'use strict'` | Add at file top |
| `console.assert()` → `expect()` | Rewrite assertion |
| Hardcoded baseURL string | Replace with `testData.baseURL` |
| Missing `afterEach` screenshot block | Inject standard block |
| K6 hardcoded threshold | Replace with `__ENV.*` reference |
| Invalid placeholder `<var>` in string | Convert to `${var}` template literal |
| Missing `sleep(1)` in K6 default fn | Inject at end of function |
| K6 `require()` → `import` | Convert to ES module syntax |

**NEVER auto-patch:**
- Locator strategy changes (selector quality is a human decision)
- Assertion logic changes (may change test intent)
- Test flow order changes
- POM method behaviour changes

## 📊 SCORING

```
Per-file score = 100 - (blockers × 25) - (majors × 10) - (minors × 2)
Overall score  = average of all file scores

Grade: A ≥ 90 | B ≥ 75 | C ≥ 60 | D ≥ 40 | F < 40

Decision:
  Any BLOCKER   → REJECT (regardless of score)
  Grade D or F  → REJECT
  Grade C       → APPROVE_WITH_WARNINGS
  Grade A or B  → APPROVE
```
